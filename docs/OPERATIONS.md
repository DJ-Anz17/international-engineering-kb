# 日常治理与建设路线

## 每周工作法

1. 所有新资料先进入 `00_待分类`；
2. 去重、判断版权/保密级别，移动到正式分类；
3. 对关键文件填写 `.meta.json`，尤其是版本、有效日期、项目、国别和合同范本；
4. 运行增量索引，处理 PDF/OCR 警告；
5. 用固定问题做抽查：能否找到正确文件、正确版本、正确位置；
6. 把验证后的项目经验写成一页式“经验卡”，而不是只保留长篇会议记录。

## 推荐资料优先级

| 优先级 | 内容 | 原因 |
|---|---|---|
| P0 | 已签合同、特别条件、补遗、澄清、关键来往函件 | 决定权利义务，版本错误代价最高 |
| P0 | 招标文件、BOQ、报价假设、供应商/分包报价 | 决定投标边界和价格 |
| P1 | 施工方案、计划、资源和现场实绩工效 | 支撑技术与履约判断 |
| P1 | 国别法律税务、劳工、签证、汇率、市场价 | 时效性强，需有效日期 |
| P1 | 风险登记册、索赔事件、经验教训 | 可直接复用到新项目 |
| P2 | 标准规范、参考书、培训材料 | 范围广，但需注意版权和版本 |

## 关键治理规则

- 一份文件只保留一个“受控版本”，旧版移入 `99_归档`，不要用文件名“最终版2”；
- 价格和工效必须带币种、基准日、税口径、单位和适用条件；
- 合同资料必须区分范本、投标版、谈判版、签署版和后续补充协议；
- 国别信息必须有来源机构和生效/查询日期；
- 项目经验应同时记录“适用条件”和“不适用条件”；
- AI 生成内容要标记为草稿，经专家确认后再进入正式知识库。

## 建议建立的检索评测集

先积累 30—50 个真实问题，每个问题记录应该命中的文件和页码，例如：

- 本项目变更通知的期限和收件人是什么？
- 哪些 BOQ 项目的工程量风险由承包商承担？
- 当地劳工配额如何影响高峰人工计划？
- 混凝土工效基准来自哪个项目，气候条件是否可比？
- 延误损害赔偿的上限与责任总上限是什么关系？

每次调整切块、模型或同义词后回归测试，关注命中率而不是只看回答是否流畅。

## 三阶段建设

### 第 1 阶段：可查（现在）

整理高价值资料、补元数据、建立 30 个评测问题。目标是 1 分钟内定位原文。

### 第 2 阶段：可审（1—3 个月）

把投标复核、合同评审、工效测算、风险登记册输出标准化；建立经人工确认的案例卡和检查清单。

### 第 3 阶段：可推（3—6 个月）

连接项目数据库、历史报价和现场实绩；增加结构化计算工具、审批、ACL 和审计日志。此阶段再评估 MaxKB/Dify/RAGFlow/Qdrant 等平台。
